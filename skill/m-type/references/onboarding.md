# 首次接入与中断恢复

先识别当前宿主，再加载 [WorkBuddy](clients/workbuddy.md)、[Codex](clients/codex.md) 或 [其他 Agent](clients/generic.md)。不要读取或打印全局配置中的凭证值。

用户请求“生成我的档案”已允许必要的只读订单查询；连接有效时直接查询。用户仅要求看演示时不查询本人账号。发现服务没有连接，给出简短引导：

> 模板和角色已经准备好。请打开[麦当劳官方 MCP 平台](https://open.mcd.cn/mcp)，登录并申请 Token，在当前 Agent 的 MCP 凭证入口填写。接好后告诉我“已连接”，我会继续读取这次可获取的订单。Token 不用发给我。

官方服务为 `https://mcp.mcd.cn`，传输 Streamable HTTP，请求头为 Bearer Token；本人完成登录验证与平台协议。安装 Skill 和连接账号是两步，ZIP 不包含凭证或自动授权。依据：[麦当劳官方说明](https://github.com/M-China/mcd-mcp-server/blob/main/README.md)。

| 可观察状态 | 下一步与用户提示 |
| --- | --- |
| 无服务或工具 | 展示当前客户端步骤；等待用户完成授权 |
| 已配置但未暴露工具 | 按宿主要求重载/新会话；不重复新增同名服务 |
| 只发现工具 | 读取实际参数，执行一次 `order-list` 验证认证 |
| 查询成功，`data:{}` | 连接成功，本次未返回列表；不能断言历史订单为零；进入缺失偏好问答 |
| 查询成功，`data:{list:[]}` | 本次返回空列表；进入缺失偏好问答 |
| 查询成功，有列表 | 读取对应详情并核验；分析记录与缺失维度 |
| 401/403 | 停止重试；请本人检查凭证或权限，再继续 |
| 429/网络临时错误 | 遵循服务等待要求，最多重试 2 次；仍失败保留进度，不变成空档案 |
| 业务失败/未知字段 | 暂停自动映射，说明具体缺失信息；不以空订单替代 |

“检查连接”在报告查询状态后结束。生成档案才继续问答。查询刚在同一任务成功，直接复用该响应；用户明确“刷新/重新查询”才重新读取。中途退出后可复用已保存的规范化输入与答案，但保留原查询时间，不能说刚刚重新查询。

当前验证：开发客户端已实测官方握手、工具发现和成功无列表返回；通用包在独立目录验证，WorkBuddy/Codex 原生 MCP 与新会话触发仍待第四阶段实测。
