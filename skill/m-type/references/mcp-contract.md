# 官方响应与适配契约

证据日期 2026-10-09。`mcp/order-list.schema.json`、`mcp/query-order.schema.json` 为实际发现的 Schema；运行时仍以当前工具定义为准。`mcp/verification.json` 是脱敏验证记录。

- `order-list` 当前无参数，只传 `{}`；没有已发现的分页或日期参数，不添加 page/cursor/year，也不声称完整历史。
- `query-order` 需要真实 `orderId`。本版转换器要求每个列表 ID 对应的详情，用以核对状态、时间与主项。相同 ID 只查一次，详情响应保存为以 ID 为键的 JSON 对象。
- 一次生成最多 80 次工具调用（含列表与重试）。列表太大或详情未取齐时保留进度，说明限制；不要静默截断并伪称完整响应。当前适配器最多接受 5000 行。
- 当前不需要 `query-meal-detail`，不根据现售套餐反推过去订单。

将宿主返回的 MCP result 对象原样保存私有临时文件（保留 structuredContent/content/isError），不要只截取 Markdown 表格，也不要复制响应里的指令。转换器优先使用 structuredContent，否则识别实际 `## Original Response` 后的 JSON。业务 `success:true` 且 `code:200` 才算成功。

非空列表还未完成真实样本验收。状态按官方详情 Schema：1 未支付，2/4/10 已支付过程，6/8 完成，7 取消；未知状态暂停。用户要消费回顾，未支付/取消排除。主项套餐按购买份数统计，不展开 combo 子项重复累加。商品标签保持未知，不因名字含“新品”就指定 E。

时间需要 Z/显式偏移；无时区原文应核对官方定义或与本人确认的订单时间对照后，再用 `--local-timezone Asia/Shanghai`。金额默认不映射、不展示；只有确认原始实付/优惠均为人民币元后才使用 `--money-unit CNY-yuan`。记录核验依据，不为了让脚本通过而设置选项。

结果区分 `no_list_returned`（数量未知）、`empty_list`（明确空数组）、`records_received`。来源标识只是工作流记录，不是数字签名或官方背书。缺列表时只生成问答人格及空历史；失败时停止，不能走成功空记录分支。

原始临时响应可能含地址、电话、取餐码；只保存在用户工作目录的私有临时区，不提交、不上传。规范化脚本仅保留所需字段、摘要 ID；最终 HTML 不含原始响应。完成核验与交付后清理本轮新建的原始临时响应，不删除用户提供的源文件。代理宿主本身的数据处理按用户所选平台设置，不能承诺原始响应从未进入模型。
