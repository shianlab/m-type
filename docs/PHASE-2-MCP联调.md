# 第二阶段：真实 MCP 联调

## 当前进度

已增加本机只读联调客户端、隐藏凭证输入、官方工具发现、参数校验和私有响应保存。2026-10-09 已用本人输入的 Token 完成握手、发现与一次 `order-list({})` 调用，返回业务成功但 `data: {}`，没有订单列表。非空真实订单样本与详情映射仍待验证。

此工具用于开发联调；后续安装版 Skill 将优先复用 Agent 自身已连接的 MCP。它不修改 Codex/WorkBuddy 的全局配置。

## 本人接入

1. 在 [麦当劳官方 MCP 平台](https://open.mcd.cn/mcp) 登录并申请自己的 MCP Token。
2. 运行 `npm run mcp:session`。
3. macOS 会显示「M-TYPE · 连接麦当劳 MCP」隐藏输入框，在其中填写 Token。不要把 Token 发进聊天、写进安装命令或提交到仓库。
4. 程序使用官方 SDK 连接 `https://mcp.mcd.cn` 并发现工具，输出 `tools_discovered` 后保持运行。

Token 只放在本次进程内存，不保存到项目文件；程序退出后再次运行需要重新输入。其他受控运行环境可以通过 `MCD_MCP_TOKEN` 环境变量注入，不提供含凭证的命令行参数。官方接入依据见 [麦当劳 MCP README](https://github.com/M-China/mcd-mcp-server/blob/main/README.md)。

## 会话协议

程序读取标准输入中的逐行 JSON。`tools_discovered` 会返回已发现的只读工具名与本机 `tools.json` 路径。先阅读实际 Schema，再构造调用参数。不要将以下协议描述误当作官方工具参数示例。

- 状态：`{"op":"status"}`。
- 调用：`op` 为 `call`，`name` 必须是已发现且允许的工具名，`arguments` 必须通过该工具实际 inputSchema 校验。
- 关闭：`{"op":"close"}`，或在终端按 Ctrl+C。

只允许 `order-list`、`query-order`、`query-meal-detail` 三个报告所需工具，具体使用顺序仍取决于发现结果。工具白名单在客户端执行，不表示官方 Token 自身被限制为只读。单次调用超时 30 秒，本次会话最多 80 次调用，45 分钟自动结束。

成功返回 `tool_result` 与私有结果文件路径。终端只显示字段结构，不回显订单值、凭证或原始服务报错。MCP 的 `isError` 会明确返回 `tool_error`；HTTP 401/403/429 等另有状态，不会当作零订单。

开发联调的 Schema 和原始响应保存在 `.local/mcp/session-*/`；目录已加入 Git 忽略，现有预览服务器拒绝访问点目录，文件尝试采用仅本人可读权限。原始响应可能含个人信息，不能将该目录放入 Skill、Release 或公开示例。字段核验和转换完成后清理原始响应，公开测试只采用合成数据。

## 真实数据核验顺序

1. 确认握手与工具发现成功，核对 `order-list` 的实际参数。
2. 执行第一笔必要的订单查询，区分成功数据、业务错误、认证失败及空列表。
3. 阅读实际返回字段，确认日期、状态、金额单位、分页终止条件及商品数量含义。
4. 必要时读订单详情；核验套餐展开方式，避免父子项目双算。
5. 只映射有证据的字段到第一阶段输入；缺优惠、标签等保持未知，由现有问答补充。
6. 标注获取时间、实际记录跨度、原始/有效条数及是否读完可用分页，再生成并核对 HTML/PNG。

已发现 `order-list` 不接收参数；`query-order` 要求 `orderId`。完整输入/输出 Schema 与不含个人数据的实测记录保存在 `references/mcp/`。当前只有 Schema 与缺少列表的成功响应，不声称订单详情已经实测。

## 接入第一阶段生成入口

使用 `npm run mcp:normalize -- --list 原始响应.json --out .local/normalized.json` 转换，再将输出交给 `npm run analyze` / `npm run render`。非空列表还需要用 `--details` 提供按订单标识索引的详情响应。

转换会区分：`no_list_returned`（未返回列表，条数未知）、`empty_list`（明确空数组）、`records_received`（返回记录），并携带查询时间与单次响应范围。业务失败、未知状态、订单标识不一致或字段类型变化会停止转换，不能补造零值。最终页面对“未返回列表”会明确说明不代表历史零订单。

基于已发现 Schema 的适配器按主项记录套餐，避免对子项数量做未经验证的展开；默认不推断经典/新品，也不转换尚未核验的金额。无时区的时间需要先核实当地时间口径，再显式传 `--local-timezone Asia/Shanghai`；金额单位核验后才允许 `--money-unit CNY-yuan`。这些选项是核验后的配置，不能为让流程通过而随意填写。

当前真实响应已转换为 `.local/mcp-normalized.json`，分析结果为 `needs_answers`；未为本人虚构偏好答案或生成冒充真实历史的报告。后续拿到非空样本，再逐项验证映射并填写实际验收结果。

本轮 57 项逻辑/命令行检查通过，另已验证 MCP 未返回列表与明确空列表的不同页面提示及离线 PNG 导出。适配器里的有订单测试数据均为合成样本，这些测试不能代替非空真实订单验收。
