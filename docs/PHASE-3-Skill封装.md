# 第三阶段：Skill 与本地安装包

2026-10-09，版本 `0.3.0`。已完成通用 Skill、接入引导、问答衔接、固定模板与素材打包、可恢复的安装行为和独立运行验证。实际客户端导入与新会话发现进入第四阶段；公开 GitHub 地址与发布许可进入第五阶段。

## 交付文件

- `dist/m-type-0.3.0.zip`：约 41.1 MB，单层 m-type 目录，完整预览包。
- `dist/SHA256SUMS`：ZIP 的 SHA-256 校验值。
- `dist/m-type/`：同版本完整解包目录，可以独立运行。
- `skill/m-type/`：Skill 指令、元数据和引用文档的编写源；代码/图片在构建时从现有实现装配，避免维护两套统计与样式。不要只复制这个源目录安装。
- `INSTALL.md`：执行安装的 Agent 的入口，以及本地试用请求。
- `output/phase3/package-verification.json`：本机独立运行的验收证据。

## 用户体验

用户说“生成我的麦门人格档案” → 检查现有麦当劳工具 → 未连接则引导官方登录、宿主凭证输入 → 查询本次可用订单 → 补问缺失偏好 → 固定脚本计算 → 选择预制角色 → 输出 HTML 与长图。

用户说“检查麦当劳连接”仅查询并报告状态；“先看演示”使用合成样本，无需账号。Skill 安装不意味着账号授权。

没有近期消费：保留真实查询状态。接口没返回列表不等于全历史零订单；补问口味、优惠、时段和复购偏好，得到 16 型之一，历史区留空并注明问答来源。不替用户选择答案，支持分次回答与中途恢复。

## 包内构成

```text
m-type/
  SKILL.md
  agents/openai.yaml
  references/                # 接入、各宿主、MCP 契约、运行、文案
  scripts/                   # 校验、规范化、分析、补答、渲染、导出、安装
  template/                  # 同一套固定 retro-v1 HTML/CSS/JS
  assets/personalities-retro-v1/  # 16 张透明角色
  assets/report-decor-v1/        # 8 个背景、门店和食物素材
  vendor/                    # html-to-image 及原始许可
  examples/                  # 仅合成样本
  package.json
  package-lock.json          # 可选自动 PNG 依赖
  package-manifest.json      # 每个发布文件的 SHA-256
  THIRD_PARTY_NOTICES.md
```

Node 20+ 可离线生成 HTML，不需要 npm 安装、在线图像模型或开发者机器路径。自动 PNG 可复用宿主浏览器运行时，或安装锁定的 Playwright 依赖及 Chromium；浏览器失败时 HTML 可继续交付并手动保存长图。

打包采用白名单，不带真实账号响应、Token、开发 MCP 客户端、node_modules、历史输出、草稿参考图或 AppleDouble 元数据。不修改全局配置。本轮只在临时目录测试安装，没有将该包写进当前用户的全局 Skill 列表。

## 已执行验证

- 59 项逻辑/CLI 测试通过，包含新增补答流程；原 16 型计算、套餐统计、隐私字段过滤和异常路径继续通过。
- 实际 ZIP 校验并解压到仓库外独立临时目录；不依赖仓库 node_modules 即可生成 HTML。
- 全部 16 个角色与 8 个装饰随包存在；校验器可发现素材缺失。
- 首次安装成功、同版本重复安装幂等；已有本地修改不会被覆盖，无关文件保留。
- 成功无列表、认证/业务失败分别处理；不回答就不出个人档案，分次回答完成后历史仍为空。
- 包内生成的 HTML 验证 320 / 390 / 1280 宽度无横向溢出，无外部网络请求，无脚本错误。
- 包内 HTML 已通过实际浏览器导出电脑与手机 PNG，分别宽 1800 / 1086 像素；复用了本机已装 Playwright，不宣称 ZIP 自带浏览器。

测试用偏好和 MCP 响应都是合成夹具，没有替本人填写答案，也没有将测试报告作为本人历史档案交付。工具发现和真实无列表查询证据沿用第二阶段；真实非空订单详情仍未取得。
